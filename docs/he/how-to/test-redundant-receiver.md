# בדיקת תצורת מקלט יתיר

יתירות שווה משהו רק אם היא נבדקת בפועל לפני הטיסה —
הנחת היסוד כאן היא ש[מקלט יתיר](../model-setup/rf-system.md#redundant-receivers)
כבר מוגדר.

!!! note "צילומי מסך בהמתנה"
    לעמוד זה עדיין אין צילומי מסך מהסימולטור — ראה [Screenshot
    Pipeline](../contributing/screenshot-pipeline.md).

## א. בדיקה בשטח

כאשר המקלט הראשי פועל ב-2.4GHz והמקלט היתיר ב-900MHz, הפעל
[Range Check](../model-setup/rf-system.md#range-check) והתרחק מהדגם
עד שהקישור ב-2.4GHz יאבד (מעבר להתראת RSSI Critical). בנקודה זו
המקלט היתיר ב-900MHz אמור לקבל את השליטה.

## ב. בדיקת שולחן

1. **ודא תצורה תקינה** — שני המקלטים מקושרים, שתי נוריות ה-LED הירוקות דולקות,
   ופקדי השליטה מגיבים כרגיל.
2. **קשר את המקלט הראשי ל-Model ID אחר** — צור דגם בדיקה זמני
   (למשל "TestRx") עם Model ID שונה, וקשר אליו את המקלט *הראשי*.
   חזור לדגם הנבדק: נורית ה-LED של המקלט הראשי אמורה להיות עכשיו
   **אדומה** (מקושר במקום אחר), ונורית ה-LED של המקלט היתיר נשארת
   **ירוקה** — ופקדי השליטה אמורים לפעול, מה שמוכיח שהמקלט היתיר
   לבדו שומר על יכולת הטיסה של הדגם.
3. **קשר מחדש את המקלט הראשי** ל-Model ID הרגיל שלו. ודא ששתי נוריות
   ה-LED ירוקות שוב ושפקדי השליטה פועלים לפני שתראה את הבדיקה כמושלמת.
