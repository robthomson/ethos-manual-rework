# 射频系统

用于配置模型的内置和/或外置射频模块、拥有者注册 ID、接收机对频以及接收机选项。模型选择使用内置还是外置模块也在此处设置——与 [系统设置](../system-setup/index.md) 中几乎所有其他项目不同，射频硬件的选择是**按模型**独立保存的，而非整机通用。

## 拥有者注册 ID {: #owner-registration-id }

这是一个 8 位字符的唯一代码（可混合使用大小写字母和数字，不支持特殊字符），接收机注册后该代码即成为其**注册 ID**。在多台发射机上设置*相同*的代码，即可在它们之间使用 **Smart Share**（智能共享）功能——请在创建需要共享的模型之前完成此设置。该功能与 EdgeTX 兼容，与 OpenTX 仅部分兼容。

## 关闭射频输出

开机过程中按住 `PAGE` 键，可在本次开机期间同时关闭内置和外置射频输出（会有警告提示确认已关闭）。模块的**状态**设置本身仍为 ON——正常重启后即恢复正常发射。

## 内置模块模式

X18/X20/X20S/X20HD 的内置模块（TD-ISRM）可在三种模式之一下运行——X20 Pro/R/RS 使用的 TD-ISRM Pro 模块与之类似，但额外支持 LoRa 以及双频串联（tandem）机型。所选模式**必须与接收机所支持的模式相匹配**，否则对频将失败；切换模式后，请仔细重新检查每个通道，尤其是失控保护行为。

- **ACCESS** —— 2.4GHz 与 900MHz 通路在同一套 ACCESS 控制下串联工作。最多可连接三台接收机，2.4GHz（24 通道）与 900MHz（16 通道）可任意组合；两个频段的回传同时有效，并按频段标记。**RX** 回传信号源会显示当前哪台接收机是活动的回传来源。
- **ACCST D16** —— 单一 2.4GHz 通路，用于旧款 “X” 系列接收机。
- **TD 模式** —— 低延迟、远距离的 2.4GHz + 900MHz 双频串联模式，用于 Tandem 系列接收机，每个频段 24 通道。

**Flex 固件**版本会增加第二个 Type（类型）栏，可在上述三种模式下切换 FLEX915M（FCC 风格 915MHz）与 FLEX868M（LBT 风格 868MHz）调制方式——所选类型必须安装相匹配的天线。欧洲用户可在 868MHz 上使用 200/500mW；在 25mW 时回传通过 868MHz 传输，在 200/500mW 时为符合法规要求，回传改由 2.4GHz 传输。

每种模式/通道数量的选择都会影响刷新率——例如在 ACCESS 下，8 通道每 7ms 刷新一次，16 通道为 14ms，24 通道为 21ms（以 8 通道为一组轮换）；配合兼容接收机（RS 系列，v2.1.7 及以上）时，Ch1-8 可使用 4ms 的 **Racing 模式**（竞速模式）。

## 注册与对频接收机（ACCESS） {: #registering-and-binding-a-receiver-access }

ACCESS 接收机的对频分两个阶段——**注册**对于每一组接收机/发射机配对只需进行一次；此后**对频**可无线重复进行，无需再按对频按钮。

**第一阶段 —— 注册**：

1. 点击 **Register**（注册）（若接收机已注册，可完全跳过此步）。
2. 按住接收机的对频按钮并给其上电；等待两个 LED 均点亮。对话框会从 “Waiting for receiver…”（等待接收机…）变为 “Receiver connected”（接收机已连接），并自动填入接收机名称。
3. 确认或编辑**注册 ID**（默认为上文的拥有者注册 ID——多台发射机之间 ID 相同才能实现 Smart Share）、**Rx name**（接收机名称）和 **UID**。UID 用于区分同一模型中共同使用的多台接收机——单台接收机保持为 0；使用多台时（例如每 8 通道一组各一台），惯例是使用 0/1/2。UID 之后无法从接收机读回，因此请在硬件上做好标记。
4. 点击 **Register**，确认出现 “Registration ok”（注册成功），然后给接收机断电——此时接收机已注册但尚未对频。

**第二阶段 —— 对频**：

!!! warning
    切勿在连接了电动马达或发动机运转的情况下进行对频。

1. 接收机断电；确认已处于正确的模块模式。
2. 点击 **RX1**（或 2/3）→ **Bind**（对频）。重复播报的 “Bind” 语音提示表示已进入对频模式。
3. **不要**按对频按钮，直接给接收机上电；在出现的 “Select device”（选择设备）列表中选择它。
4. 确认出现 “Bind successful”（对频成功）。将遥控器和接收机都重新上电——接收机绿灯亮、红灯灭表示链接已建立。除非更换其中一方，否则无需重复对频。
5. 如使用多台接收机，请对 RX2、RX3 重复上述操作。

## 接收机选项

在接收机上电的状态下，点击其 RX 按钮可进行以下操作：

- **Options**（选项）—— **Telemetry**（该接收机的回传开/关）、**Reduced telemetry power 25mW**（降低回传功率至 25mW，相对于常规的 100mW——当附近的舵机受到射频干扰时很有用）、**High PWM Speed**（舵机刷新率由 18ms 提升为 7ms——请确认舵机能够承受）、**Telemetry port**（回传端口：S.Port/F.Port/FBUS）、**SBUS**（16 或 24 通道——启用 24 通道前，所连接的每台 SBUS 设备都必须支持 SBUS-24），以及 **Channel Mapping**（通道映射），可将通道重新映射到指定的接收机针脚。
- **Share**（共享）—— 将接收机移交给拥有者注册 ID *不同*的另一台 ACCESS 遥控器。在源遥控器上点击 Share（其绿灯熄灭）；在目标遥控器上按常规方式执行 Bind——由于 ID 会自动转移，Share 可跳过重新注册。在源遥控器上退出即结束共享；重新对频可将其移回。（如果所有遥控器已共用同一个拥有者注册 ID，则完全不需要此功能——直接在需要控制它的遥控器上对频即可。）
- **Reset bind**（重置对频）—— 用于在 Share 之后清理并恢复自己的对频；操作完成后请给接收机重新上电。
- **Factory reset**（恢复出厂设置）—— 重置接收机并清除其 UID，完全取消注册。

在接收机**断电**状态下，同一 RX 按钮提供 **Options**（等待接收机连接）、**Bind**（例如重新对频此前在别处对频过的接收机）以及 **Clear**（等效于 Reset bind）。

## 冗余接收机 {: #redundant-receivers }

可将第二台接收机对频到空闲的 RX 插槽以实现冗余——2.4G 与 900M 可互为备份。FrSky 的冗余机制按**帧**评估，始终采用可用的最佳数据帧（主动/主动切换），因此控制权可根据需要在接收机之间逐帧切换。

1. 将冗余接收机的 SBUS Out 接到主接收机的 SBUS In。
2. 启用对应的内置射频模块（例如 900M）并设置其天线/功率。
3. 注册新接收机（若尚未注册），然后按上文所述将其对频到空闲的 RX 插槽。
4. 确认其绿灯点亮——此时它已被列为冗余接收机。

## 失控保护 {: #failsafe }

失控保护数据大约每 10 秒由发射机重发一次；在 TD/TW/AP/AP Plus 接收机上，该数据还会保存在接收机端，因此接收机重启后仍然有效。在任何为接收机新增此行为的固件升级之后，请仔细重新检查失控保护设置。

- **Hold**（保持）—— 保持最后接收到的通道位置。
- **Custom**（自定义）—— 逐通道设置：**Not Set**（未设置）、**Hold**（保持）、**Custom**（固定值——点击箭头图标可捕获当前值，也可直接输入数值）或 **No Pulses**（无脉冲）。
- **No Pulses**（无脉冲）—— 直接停止输出脉冲，适用于在信号丢失时具有自身返航行为的飞控。
- **Receiver**（接收机）——（X 系列或更新的接收机）改为在接收机本身上设置失控保护。

!!! warning
    在依赖所选失控保护设置之前，请务必仔细测试。

## 距离测试 {: #range-check }

每次使用新的或有改动的配置飞行前，都应在场地上执行此测试。选择 **Range Check** 会刻意降低发射功率（重复的语音提示会确认进入该模式），并实时显示 VFR%/RSSI 以评估链路质量。FrSky 距离测试的功率约为相对于正常 +20dB 工作电平的 −10dB；在遥控器与接收机均离地 1m 的情况下，通常在约 30m 处出现严重告警——若在正常条件下明显近于此距离，可能说明存在问题。

在对频了多台接收机时，距离测试数据每个频段一次只显示一台活动接收机的信息——关闭当前活动的那台，即可让下一台（按 0/1/2 优先级，可通过 **RX** 传感器查看）接管，从而依次检查每台接收机。

## 外置模块与第三方射频模块

FrSky 外置模块（XJT Lite、R9M Lite、R9M Lite Pro、TWIN Lite Pro）采用与内置模块相同的注册/对频流程，但通道数量、功率等级和天线要求因协议而异——具体数值请参阅对应模块的说明书。

**ELRS**（ExpressLRS）既可通过 TWIN Lite Pro 模块的 ELRS 模式使用，也可通过原生 ELRS 模块使用（后者需将 ELRS Lua 脚本安装到 `scripts/elrs` 后才会作为模块选项出现）。共 12 通道；主要设置包括 **Packet Rate**（包速率，在延迟与距离之间取舍）、**Telemetry Ratio**（回传发送频率，1:1 至 1:128）、**Switch Mode**（开关模式：**Hybrid** —— 多数辅助通道降为 2–3 档位以降低延迟；或 **Wide** —— 完整的 64–128 级分辨率）、**Model Match**（模型匹配）以及 **Tx Power**（发射功率，10mW–1000mW，可选 **Dynamic Power** 动态功率，根据链路质量自动调整——需启用回传）。

**第三方模块**（目前除 ELRS 外还有 Ghost、Multi-protocol、Crossfire）各自需要用户自行安装相应的 Lua 脚本——参见 [截图流程](../contributing/screenshot-pipeline.md) 中关于 `scripts/` 的说明，以及 rcgroups 上的 *Third-Party External Modules* 主题帖。只有在脚本安装完成后，模块的条目才会出现在射频界面上。Multi-protocol 模块（IRX4 Lite）还可直接从 [文件管理器](../system-setup/file-manager.md) 刷写固件：将固件文件复制到 `Firmware/`，然后执行 **Flash external multimodule**（刷写外置多协议模块）。
