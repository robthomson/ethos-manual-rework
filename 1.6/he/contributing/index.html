    תרומה לפרויקט¶

    מדוע מדריך זה קיים¶

    המדריך הקודם (ethos-manual) התפצל לשני חצאים מנותקים לכל שפה. עץ האנגלית מעולם לא היה יותר ממתקן ליצירת צילומי מסך — סקריפטי shell שמפעילים את סימולטור Ethos האמיתי דרך API של מאקרו ב-Lua כדי לצלם את מסכי הממשק — בלי שום מקור Markdown (או כל טקסט פשוט אחר) לטקסט עצמו של המדריך; הטקסט האנגלי התקיים אך ורק כערימה של קבצי PDF/ODT מיוצאים. עץ הצרפתית, לעומת זאת, היה ייצוא GitBook כתוב במלואו עם תוכן אמיתי, אך נבנה ותוחזק באופן עצמאי, עם סט צילומי מסך נפרד משלו שהודבק ידנית. לשפות אחרות לא היה אף אחד מהשניים. לא היה מקור אמת יחיד לתרגם ממנו, ולא הייתה כל דרך לדעת מתי דף מתורגם נעשה לא מעודכן ביחס למקור האנגלי (שכלל לא היה קיים).

    מאגר זה מתחיל מחדש בפורמט אחד לכל דף, בכל שפה: Markdown פשוט, שנבנה עם MkDocs Material (אותה מערכת המשמשת את wingflight-docs), ומופץ ל-GitHub Pages בכל דחיפה ל-main.

    תהליך העבודה¶

    אין CMS או עורך web לפני התוכן — כותבים ומתרגמים עובדים ישירות ב-git, בדיוק כמו בכל שינוי אחר במאגר הזה:

    1. פתחו ענף מתוך main (במאגר הזה עצמו — ראו את ההערה על forks בהמשך).
    2. ערכו את קובצי ה-.md הרלוונטיים תחת docs/en/.
    3. צפו בתצוגה מקדימה מקומית באמצעות mkdocs serve (ראו את README בשורש), או פשוט פתחו pull request והשתמשו בתצוגה המקדימה האוטומטית של ה-PR המתוארת להלן.
    4. פתחו pull request.

    צילומי מסך שמופנים אליהם מדף מסוים נמצאים לצידו ב-docs/en/assets/ והם פשוט קישורי תמונה של Markdown — בלי תחביר מיוחד. ראו צינור צילומי המסך להסבר כיצד הם נוצרים.

    תצוגות מקדימות ל-PR¶

    כל pull request מול main מקבל תצוגה מקדימה חיה משלו, שנבנית ומופצת אוטומטית על ידי .github/workflows/pr-preview.yml: בכתובת manual.rt-rc.com/pr-preview/<PR number>/, מקושרת בתגובת בוט ב-PR ומתעדכנת בכל דחיפה. היא מוסרת אוטומטית כשה-PR נסגר. האתר הראשי עצמו (manual.rt-rc.com) אינו מושפע — התצוגות המקדימות שוכנות לצידו בתיקיית pr-preview/ בענף gh-pages, ששורדת כל הפצה לייצור.

    זה פועל רק עבור ענפים שנדחפו ישירות למאגר הזה, לא ל-forks — PR מ-fork לא יקבל תצוגה מקדימה חיה (GitHub מונע במכוון הרשאות כתיבה ל-GITHUB_TOKEN בתהליכי pull_request שהופעלו מ-fork, כדי ש-fork לא יוכל להשתמש ב-CI לדחיפת תוכן שרירותי ל-gh-pages). תורמים מ-fork יכולים עדיין לצפות בתצוגה מקדימה מקומית עם mkdocs serve.

    ניהול גרסאות¶

    מדריכים של מספר גרסאות קושחה (למשל 1.6 יחד עם Ethos26 עתידי) שוכנים באותו מאגר כענפים נפרדים, כשכל אחד מופץ לנתיב manual.rt-rc.com/<version>/ שלו עם תפריט בחירת גרסה — ראו ניהול גרסאות לתכנית המלאה וכיצד ליצור גרסה חדשה.

    תכנית התרגום¶

    מתרגמים (אנושיים או AI) עובדים ישירות ב-git, בדיוק כמו בכל שינוי אחר — בלי CMS, בלי אפליקציית תרגום נפרדת. פיילוט ראשון בצרפתית (מספר דפים בודדים) הוכיח את המנגנון מקצה לקצה; כך זה עובד בפועל.

    הוספה/עדכון של תרגום¶

    1. פתחו ענף, צרו/ערכו את docs/<locale>/<same path as the English page>, ותרגמו את הטקסט. השאירו טקסט מילולי-קוד (שמות מקשים כמו ENT, RTN, שמות רכיבי ממשק המוצגים על המסך) כמו שהם.
    2. סמנו את הדף בציון ה-commit האנגלי שממנו תורגם:
    ---
translated_from: <commit sha of docs/en/... at translation time>
---

    מצאו את ה-sha באמצעות git log -1 --format=%H -- docs/en/<path>. 3. אם לדף האנגלי יש כותרת שדפים אחרים מקשרים אליה דרך עוגן (בדקו בחיפוש #that-heading-slug בכל docs/en/), אל תאפשרו ל-slug שנוצר אוטומטית עבור הכותרת המתורגמת לשנות את היעד — קבעו במפורש את אותו מזהה קבוע ובלתי תלוי שפה באמצעות attr_list (מופעל כבר):

    ## Choisir une source {: #choosing-a-source }

    דילוג על כך אינו שובר את הבנייה, אך הוא שובר בשקט את הגלילה לעוגן עבור כל דף אחר, שעדיין לא תורגם, שמקשר לאותה כותרת דרך מנגנון הנפילה לאנגלית. 4. פתחו PR — צפו בתצוגה מקדימה כמו בכל שינוי אחר, כולל מחליף השפות.

    צילומי מסך¶

    אין מה לשכפל מראש. mkdocs-static-i18n נופל בחזרה לקובץ האנגלי עבור כל נכס שאין ללוקאל עותק משלו ממנו — ה-../assets/foo.png של דף מתורגם פשוט עובד, ללא שינוי, ומציג את צילום המסך האנגלי, עד שמוסיפים צילום מקומי אמיתי באותו שם קובץ תחת docs/<locale>/assets/, שדוחה בשקט את הנפילה לאנגלית מאותו רגע.

    ל-de ול-fr יש כבר צילומי מסך מקומיים אמיתיים — לא צולמו כאן, אלא יובאו בכמות מהמאגר הישן ethos-manual, שהתברר שיש בו סטים כמעט שלמים של צילומי מסך לכל שפה שצוות FrSky עצמו כבר צילם (german/assets/ ולצרפתית french_LT/assets/ — השלם מבין שני סטי הנכסים הצרפתיים שלו, ולא french/assets/ הקטן יותר שה-README שלו מתאר כ"חצי הדרך"). שמות הקבצים תואמים ל-docs/en/assets/ שלנו ביחס 1:1, ולכן הייבוא היה העתקה ישירה: 586 מתוך 589 צילומי המסך שאליהם אנו מפנים כיום נכנסו לשתי השפות במעבר אחד, בלי שום סימולטור. אותם בודדים שלא התאימו (2-3 קבצים, בעיקר דפים חדשים יותר שהמאקרואים של המאגר הישן מעולם לא כיסו) עדיין נופלים בחזרה לאנגלית כרגיל.

    עבור כל לוקאל מלבד de/fr, או כדי לסגור את אותם אחוזים אחרונים, צילום צילומי מסך חדשים מחייב את צינור צילומי המסך — העברה/הרצה של מתקן המאקרו האמיתי מול הסימולטור — שכן העבודה הזו לא נעשתה כבר במאגר המקורי.

    מעקב אחר התיישנות¶

    מצב התרגום נוצר אוטומטית לפני כל בנייה (hooks/i18n_status.py, מחובר דרך hooks: שב-mkdocs.yml — רץ מקומית, בתצוגות מקדימות של PR ובייצור באותה מידה, תמיד עדכני, ומעולם לא נשמר ב-git) ומשווה את סמן ה-translated_from של כל לוקאל מול ה-commit האחרון שבו שונה כל דף אנגלי: עדכני, מיושן (האנגלית התקדמה), או חסר. אותו דף הוא רשימת העבודה — בלי GitHub Issues, בלי חיפוש בלוגים של Actions.

    תרגום אוטומטי (אופציונלי)¶

    scripts/translate.py הוא סקריפט מקומי עצמאי (לא חלק מבניית האתר או מה-CI) שמעביר את אותה רשימת עבודה של חסרים/מיושנים דרך Claude API כדי להפיק תרגום טיוטה ראשונית לכל דף, מסומן אוטומטית ב-frontmatter translated_from: הנכון:

    pip install anthropic pyyaml   # if not already installed
export ANTHROPIC_API_KEY=...   # or use `ant auth login`

python scripts/translate.py --dry-run       # see what's queued, no API calls
python scripts/translate.py --only fr       # translate everything missing/stale for French
python scripts/translate.py --pages model-setup/mixes.md   # just one page

    כברירת מחדל הוא קורא כל לוקאל מתוך הגדרות התוסף i18n שב-mkdocs.yml (--only מגביל ללוקאלים מסוימים), מדלג על כל מה שכבר עדכני אלא אם מועבר --force, ואינו מבצע commit או push מעולם — הוא רק כותב קבצים תחת docs/<locale>/, בדיוק כאילו עררכתם אותם ידנית. סקרו את ה-diff, בצעו את בדיקת קיבוע העוגנים עבור כל כותרת שתורגמה מחדש, ואז פתחו PR כרגיל.

    הנחיית המערכת מזריקה ל-Claude מראש את תחום המדריך (קושחת המשדר FrSky Ethos, קהל חובבי RC) ורשימת מונחים שאסור לתרגם לעולם (שמות מקשים פיזיים, שמות פרוטוקולים, שמות מותגים) — אותה טכניקה שבה משתמש מאגר האחות rotorflight-lua-ethos-suite בסקריפט bin/i18n/auto-translate.py שלו. לכל לוקאל נתמך יש מילון מונחים משלו המשולב ב-GLOSSARIES שבסקריפט, לצורך עקביות טרמינולוגית מהדף המתורגם הראשון.

    הקמת לוקאל חדש לגמרי מאפס — מבחירת קוד הלוקאל הנכון ועד תרגום, צילומי מסך, תיקוני עוגנים ותוויות ניווט — היא תהליך שניתן לחזור עליו מקצה לקצה: ראו הוספת שפה חדשה למדריך המלא.

    תוויות ניווט (nav_translations)¶

    תוויות של לשוניות וסרגל צד ב-nav: (למשל "Model Setup") אינן מאמצות אוטומטית את כותרת הדף המתורגמת של הלוקאל, אלא אם לרשומת הניווט אין תווית מפורשת כלל (למשל - how-to/index.md — ואז MkDocs משתמש בכותרת ה-H1 של אותו דף). בכל מקום שבו nav: נותן מפורשות מחרוזת Label: path.md, או מגדיר מקטע (Model Setup: כמפתח מילון עם צאצאים), אותה תווית נשארת באנגלית עד שמפת ה-nav_translations של הלוקאל ב-mkdocs.yml מכסה אותה — היא מתווספת ללוקאל ברגע שכיסוי הדפים שלו מקיף דיו, כך שתרגום המסגרת לפני רוב התוכן לא ייראה מוזר. המפה של fr מולאה כאשר הצרפתית הגיעה לכיסוי דפים מלא; כל תווית עלה הועתקה מילה במילה מכותרת ה-H1 המתורגמת של אותו דף, כך שהטקסט בסרגל הצד תואם בדיוק לכותרת הדף.
